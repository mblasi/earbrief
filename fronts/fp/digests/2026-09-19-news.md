Functional programming is reshaping how teams build agents. The shift is from imperative mutation and interleaved action to pure state machines. Think Elm Architecture at scale.

An agent, functionally, is a pure function. State plus message goes in. New state and effects come out. Deterministic. Replayable. This matters because debugging agents at scale requires reproducibility. Given identical state and messages, the agent always produces identical outputs. Red-teaming becomes tractable when you can replay a problematic execution path with confidence.

The key insight is that logic and effects are decoupled. An agent declares which side effects it will perform—API calls, memory writes, tool invocations—without executing them. This enables safe simulation. You can test an agent's decision logic in isolation, then separately test the effect execution layer. Infrastructure teams handle the side effects safely. Agent teams focus on the decision logic.

Type safety follows. David Nolen's work on ClojureScript agents shows immutable message passing scales to complex orchestration. The framework handles concurrency. No locks. No explicit state sharing. Message-driven actors, each with pure transition functions.

Algebraic data types encode tool schemas. Instead of JSON schemas, frontier labs now define action spaces using sum types. An agent action is one of: API call, memory write, or escalate. The compiler checks exhaustiveness. An agent handles all possible action types or the code doesn't compile. Invalid states become unrepresentable.

Memory is immutable logs. Each agent decision is recorded as an event. State is reconstructed by replaying the log from the beginning. This gives auditability by default. Every action has a timestamp and context. Incorrect decisions can be undone by removing events and replaying. Multi-agent systems synchronize by exchanging logs, not by sharing mutable memory.

Simon Peyton Jones' recent work shows how to encode neural network shapes as types. Dimension mismatches fail at compile time, not runtime. Apply this to agents: "this tool requires prior context lookup" becomes a type constraint. Agent code that violates it fails before running.

LLM output parsing becomes reliable with parser combinators. Small, reusable parsers built from pure functions. Combine them with operators: choice, sequence, repetition. The result is readable, composable, and type-checked. Bartosz Milewski's talks cover Parsec in Haskell and Nom in Rust. Both enable LLMs to produce validated, structured outputs that integrate seamlessly with agent logic.

Data pipelines are declarative transformations. Polars, Scala Spark, Clojure Specter treat pipelines as compositions of pure functions. Filter, map, group, reduce. Deterministic. Inspectable. Each stage produces intermediate data for debugging. Reuse sub-pipelines across experiments. Functional reactive programming scales multi-agent choreography without explicit control flow.

Domain-driven design in functional languages uses types to encode constraints. A user ID is not just an integer; it is the type UserId. A tool request is type ToolRequest. The compiler prevents accidental mixing. Agent state is an aggregate—a cluster of entities with strong consistency. Immutability enforces aggregate boundaries automatically.

Testing leverages property-based testing. QuickCheck in Haskell, Hypothesis in Python, Proptest in Rust. Define an invariant: agent memory never loses context, no matter how many messages arrive in what order. The framework generates randomized tests to falsify the invariant. When it finds a counterexample, it shrinks to the minimal failing input, speeding debugging.

The functional agent stack is: pure state machines decoupled from side effects; immutable event logs for auditability and reversibility; type systems that prevent entire categories of bugs; composable transformations that reduce code duplication; property-based testing that catches edge cases manual tests miss.

Build agents functionally and the full contract becomes explicit. These are the states. These are the transitions. These are the effects. These invariants always hold.
