Programación funcional está remodelando cómo equipos construyen agents. El shift es de mutación imperativa y acción intercalada a máquinas de estado puras. Piensa Elm Architecture a escala.

Un agent, funcionalmente, es una función pura. Estado más mensaje entra. Nuevo estado y efectos salen. Determinístico. Reproducible. Esto importa porque debugging de agents a escala requiere reproducibilidad. Dado estado idéntico y mensajes, el agent siempre produce outputs idénticos. Red-teaming se vuelve tractable cuando puedes reproducir un path de ejecución problemático con confianza.

El insight clave es que lógica y efectos están desacoplados. Un agent declara qué side effects ejecutará—llamadas API, escrituras de memoria, invocaciones de herramientas—sin ejecutarlos. Esto habilita simulación segura. Puedes testear lógica de decisión del agent aisladamente, luego por separado testear la capa de ejecución de efectos. Equipos de infraestructura manejan los side effects seguramente. Equipos de agent se enfocan en lógica de decisión.

Type safety sigue. El trabajo de David Nolen en agents de ClojureScript muestra que message passing inmutable escala a orquestación compleja. El framework maneja concurrencia. Sin locks. Sin state sharing explícito. Actores basados en mensajes, cada uno con funciones de transición puras.

Algebraic data types codifican esquemas de herramientas. En lugar de esquemas JSON, laboratorios frontera ahora definen espacios de acción usando sum types. Una acción de agent es una de: API call, memory write, o escalate. El compilador chequea exhaustiveness. Un agent maneja todos tipos de acción posibles o el código no compila. Estados inválidos se vuelven no representables.

Memoria son logs inmutables. Cada decisión de agent se registra como evento. Estado se reconstruye reproduciendo el log desde el comienzo. Esto da auditabilidad por defecto. Cada acción tiene timestamp y contexto. Decisiones incorrectas pueden deshacerse removiendo eventos y reproduciendo. Sistemas multi-agent sincronizan intercambiando logs, no compartiendo memoria mutable.

El trabajo reciente de Simon Peyton Jones muestra cómo codificar formas de redes neuronales como tipos. Desajustes de dimensión fallan en compile time, no runtime. Aplica esto a agents: "esta herramienta requiere lookup previo de contexto" se vuelve type constraint. Código de agent que lo viola falla antes de ejecutar.

Parsing de output de LLM se vuelve confiable con parser combinators. Parsers pequeños, reutilizables construidos de funciones puras. Combínalos con operadores: choice, sequence, repetition. El resultado es legible, componible, y type-checked. Las charlas de Bartosz Milewski cubren Parsec en Haskell y Nom en Rust. Ambos habilitan LLMs producir outputs validados, estructurados que se integran sin fricción con lógica de agent.

Data pipelines son transformaciones declarativas. Polars, Scala Spark, Clojure Specter tratan pipelines como composiciones de funciones puras. Filter, map, group, reduce. Determinístico. Inspectable. Cada etapa produce datos intermedios para debugging. Reutiliza sub-pipelines entre experimentos. Functional reactive programming escala coreografía multi-agent sin control flow explícito.

Domain-driven design en lenguajes funcionales usa tipos para codificar constraints. Una user ID no es solo integer; es tipo UserId. Una tool request es tipo ToolRequest. El compilador previene mezcla accidental. Estado de agent es un aggregate—cluster de entidades con consistencia fuerte. Immutabilidad refuerza límites de aggregate automáticamente.

Testing aprovecha property-based testing. QuickCheck en Haskell, Hypothesis en Python, Proptest en Rust. Define invariante: memoria de agent nunca pierde contexto, sin importar cuántos mensajes llegan en qué orden. El framework genera tests aleatorizados para falsificar el invariante. Cuando encuentra contraejemplo, lo simplifica al input fallido mínimo, acelerando debugging.

El stack funcional de agents es: máquinas de estado puras desacopladas de side effects; logs de eventos inmutables para auditabilidad y reversibilidad; sistemas de tipos que previenen categorías enteras de bugs; transformaciones componibles que reducen duplicación de código; property-based testing que atrapa edge cases que tests manuales pierden.

Construye agents funcionalmente y el contrato completo se vuelve explícito. Estos son los estados. Estas son las transiciones. Estos son los efectos. Estos invariantes siempre se mantienen.
