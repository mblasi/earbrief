Today's stories are mostly about capacity meeting its limits: an agent harness tightens its own permission checks after finding real gaps between what it approves and what the shell actually does, a two point eight trillion parameter model gets so popular it runs out of chips to serve it, and two governments spend the week deciding, in very different ways, who gets to open the door on someone else's platform.

Five stories, ranked by technical significance.

Story one. Claude Code shipped a run of point releases this week closing a set of permission-check gaps that all share the same shape: the checker and the shell disagreed about what a command actually does.

Across builds two one two one two through two one two one five, landing July nineteenth, Anthropic fixed a permission-check bypass affecting commands run in Windows PowerShell five point one sessions, and separately fixed Bash permission checks to fail closed on file-descriptor redirect forms that Bash parses differently than the permission analyzer does. In both cases the static analyzer that decides whether a command is safe to auto-run was reading the command one way, while the actual shell interpreting it at execution time read the same text a different way, which is exactly the kind of gap that lets an approved-looking command do something the approval never covered. The same set of releases also made commands over ten thousand characters always prompt for confirmation instead of running automatically, tightened handling of Docker commands carrying daemon-redirect flags, and, in the most recent build, stopped the coding agent from auto-running its own verify and code-review skills, requiring an explicit invocation instead.

To see why that parsing gap matters, consider what it takes to build a permission analyzer at all: it has to look at a command string before anything runs and decide, statically, whether the effect of running it stays inside an approved boundary, like writing only to files under a given directory. That only works if the analyzer's model of what the string does matches what the real shell does with the same string. Bash's file-descriptor redirect syntax has more than one valid form for accomplishing the same redirection, and if the analyzer recognizes some forms but not others, a command using an unrecognized form can slip through looking harmless while actually redirecting output somewhere the analyzer never considered. Windows PowerShell five point one has its own long history of quoting and escaping quirks that differ from PowerShell's newer cross-platform version, which is exactly the kind of version-specific behavior a general analyzer can miss if it was built and tested against the newer one.

Sharp takeaway: this is what hardening an autonomous coding agent actually looks like day to day, and it's worth paying attention to even though none of it is a headline model release. It isn't one big safety announcement, it's a steady stream of narrow fixes closing the gap between what a permission system thinks a command will do and what the interpreter underneath it actually does, which is precisely the class of bug that turns an allowlist into decoration rather than a control. If you're running an agent harness in an auto-approve mode, on this one or one you built yourself, the PowerShell and Bash fixes are a reminder that a permission analyzer has to agree with the exact parser executing the command, on every shell and version you support, not just with a reasonable reading of it, and that gap is where the real exploits live.

Story two. Moonshot AI's Kimi K3, the two point eight trillion parameter open-weight model that made headlines just four days ago, got popular enough by yesterday to run its own hosting into the ground.

Kimi K3 launched around July sixteenth with a one-million-token context window and native multimodal input, with full weights still scheduled for public release on July twenty-seventh under a modified MIT license. By July nineteenth, only two days after subscriptions opened, usage had pushed Moonshot's graphics processing unit capacity close enough to its ceiling that the company paused new sign-ups entirely, posting that it was prioritizing available compute for existing subscribers while it expanded infrastructure and reopened new spots in batches. Existing subscriptions were unaffected; new ones simply stopped being accepted.

Sharp takeaway: publishing weights that top a benchmark table and actually being able to serve them to everyone who wants them are two different problems, and the gap between them is measured in graphics processing units, not parameters. A two point eight trillion parameter mixture-of-experts model, even with only a fraction of those parameters active per token, still needs enough high-bandwidth memory across enough accelerators to hold the full expert set and the growing key-value cache for every concurrent user, and demand that outpaces a launch plan by this much this fast is exactly the scenario capacity planning for a serving stack is supposed to catch before it happens in public. Worth reading next to yesterday's story about DeepSeek's hybrid attention architecture, which exists specifically to make a huge context window cheaper to serve: Kimi K3 keeps something closer to full attention throughout rather than DeepSeek's compressed, selective retrieval, and running out of capacity two days after launch is the kind of real-world signal that a model's serving cost, not just its benchmark scores, is what determines whether an architecture choice actually holds up at demand. When you're evaluating a new open-weight release, whether you can get an inference provider to actually run it for you, at a price you'd pay, without a waitlist, is a separate question from whether the paper's numbers look good, and today's news answers that question for Kimi K3 less favorably than Monday's did.

Story three. The European Commission told Google exactly which doors it now has to unlock on Android, and the list is a genuinely useful reference for anyone building a competing AI assistant.

On July sixteenth, the Commission issued two sets of binding specification measures under the Digital Markets Act. The first covers interoperability: Google has to open eleven Android feature groups that assistants depend on, so a competing assistant can be triggered by voice the way "Hey Google" triggers Gemini today, can perform actions inside other apps on a user's behalf, can be delegated a task like booking a taxi, can offer suggested replies inside chat apps, and can be asked about a place the user recently visited. The second covers data: Google has to share portions of the search data that only Google Search collects at the scale needed to be useful, meaning the click and query patterns across billions of searches that a competitor could otherwise only approximate, with the data anonymized first and competitors restricted to using it for improving their own search or assistant products, not advertising or profiling. Competing assistants gain access to the Android features starting July twenty twenty-seven; the search data sharing starts January twenty twenty-seven.

Sharp takeaway: strip away the regulatory framing and this is an unusually specific list of the operating-system-level hooks an agentic assistant needs to compete on a phone: a voice trigger, permission to act inside other apps, and a delegation path for multi-step tasks. That's a decent checklist to hold your own agent design against even if you never touch Android's compliance APIs directly, since it names the exact capabilities platform owners currently keep to themselves. The eighteen-month runway before enforcement means nothing changes for users soon, but it does tell you which APIs to expect Google to formalize, and worth watching whether Apple faces a parallel order for iOS given it operates under the same regulation.

Story four. TSMC's second-quarter earnings were less interesting than the number the company attached to next quarter's ambitions: another hundred billion dollars into Arizona, on top of what was already there.

Taiwan Semiconductor Manufacturing Company reported record quarterly profit of twenty-two billion dollars, up seventy-seven percent year over year, on revenue of forty point two billion dollars, up thirty-six percent, driven by demand for AI accelerator chips. Alongside the results, the company committed an additional hundred billion dollars to its Arizona operations, bringing its total US pledge to two hundred sixty-five billion dollars across ten fabrication plants and two advanced packaging facilities, with the new capacity targeting the two-nanometer node and below. The company raised its 2026 capital expenditure guidance to a range of sixty to sixty-four billion dollars, up from fifty-two to fifty-six billion, and lifted its full-year revenue growth guidance to more than forty percent.

Sharp takeaway: the packaging facilities are the detail worth remembering more than the fab count. Advanced packaging, not raw wafer capacity, has been the recurring bottleneck between a chip design and an AI accelerator you can actually buy: modern accelerators stack multiple compute dies next to high-bandwidth memory using techniques like chip-on-wafer-on-substrate packaging, and that stacking step has its own separate, historically much more limited production capacity than wafer fabrication itself, which is why accelerator supply has lagged wafer output even when fabs were running at full tilt. A capital-expenditure number this large, with packaging called out specifically alongside two-nanometer fabs, is a better three-year-out signal for whether AI compute stays scarce or starts loosening up than any individual model's benchmark numbers, precisely because fabs and packaging lines take years to come online regardless of how fast the models on top of them improve, and Kimi K3's graphics processing unit shortage two stories ago is a preview of what happens when demand outruns whichever of the two, fab or packaging, is actually the binding constraint at the time.

Story five. The World AI Conference in Shanghai closed today after four days that produced a rival governance body more concrete than most conference announcements manage.

The conference drew more than eleven hundred companies showing roughly three thousand products across a showcase floor larger than one hundred thousand square meters, including Huawei's Atlas nine-fifty computing cluster, positioned as a domestic alternative to Nvidia-based training and inference clusters for buyers cut off from US export channels, a fleet of humanoid robots and dexterous robotic hands, and what organizers billed as the world's first agentic AI phone. Xi Jinping delivered his first keynote address at the event. The concrete outcome was the founding of the World Artificial Intelligence Cooperation Organization, a China-headquartered intergovernmental body signed by twenty-nine founding countries including Pakistan, Russia, and Kazakhstan, explicitly framed as an alternative to US-led AI governance efforts.

Sharp takeaway: read next to today's European Commission order, the pattern is two different regulatory blocs setting incompatible rules for the same technology at the same time, one forcing interoperability onto an incumbent platform, the other building a parallel standards body outside that platform's reach entirely. Neither move changes what you can build this week, but the direction both are pointing in, more jurisdictions writing their own rules for what an AI assistant or model is allowed to do, is the same fork in the road this show flagged when covering the proposed US executive order on open models: which governance bloc a country or company aligns with is quietly becoming a real constraint on which models and platforms are actually available to build on, not just a compliance footnote.

Now, what to watch. Watch whether Moonshot's compute crunch pushes back Kimi K3's promised July twenty-seventh open-weights release, since a capacity problem serving the hosted version is a reasonable predictor of trouble getting weights out the door on schedule too, and watch whether independent benchmarks of the eventual open weights hold up as well as the hosted preview's numbers did. Watch whether other agent harnesses beyond Claude Code publish similar postmortems about permission analyzers disagreeing with their underlying shell parser, because that shape of bug is a property of the pattern, not a property of any one vendor's implementation, and any team running its own auto-approve agent loop should be auditing for the same gap rather than assuming it's someone else's bug to fix. Watch which of the eleven Android feature groups Google actually opens first once its implementation window starts, since the order will tell you which of those capabilities Google considers least threatening to give up, and whether Apple ends up facing a parallel order for iOS under the same regulation. Watch TSMC's next quarterly capital-expenditure update for whether packaging capacity is growing as fast as fab capacity, since a mismatch there is exactly what would keep accelerator supply tight even as wafer output rises. And watch what the new China-led AI governance body actually produces in its first few months, binding rules or joint statements, since that distinction is the difference between a second real regulatory track and a diplomatic photo opportunity, the same distinction worth applying to WAICO that this show has applied all month to self-reported benchmark claims: an announcement is not yet an outcome.
