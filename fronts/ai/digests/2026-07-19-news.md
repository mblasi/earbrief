Today's stories are really about the gap between shipping and claiming: one lab quietly solved the ugliest part of long context and put it into production, one lab's math results are outrunning the peer review that would confirm them, and one lab has now missed the same launch date three times running.

Five stories, ranked by technical significance.

Story one. DeepSeek graduated its V4 model family from preview to a stable, official release this week, and the interesting part isn't the parameter count, it's that it quietly rebuilt what attention even means for long context.

DeepSeek-V4-Pro, a one point six trillion parameter mixture-of-experts model with forty-nine billion active per token, and its smaller sibling V4-Flash, first shipped as a preview back in April; this week's release is the graduation to stable, general availability, alongside a new peak and off-peak pricing scheme that charges double during Beijing business hours. The headline number everyone will quote is the one-million-token context window, but ordinary softmax attention scales quadratically with sequence length, so a naive million-token context would be prohibitively expensive to actually run, not just to advertise. DeepSeek's fix is a hybrid attention architecture that interleaves two different mechanisms across the model's layers instead of using one uniformly. Compressed sparse attention takes a learned, token-level compressor and consolidates every few tokens along the sequence into a single key-value entry, using softmax-gated pooling with a learned positional bias, getting roughly a four-times reduction before anything else happens. On top of that, a lightning indexer running in four-bit floating point picks out only the top few most relevant compressed blocks for each query to attend to, rather than attending to everything. A second, more heavily compressed pathway handles the bulk of distant history, while a small, exact, uncompressed window is kept for the most recent tokens, so nothing close-range gets blurred by compression. The company reports that at the full one-million-token context length, V4-Pro needs only twenty-seven percent of the inference compute and ten percent of the key-value cache memory that its previous generation, V3.2, required for the same context length, while posting open-weight state-of-the-art results on agentic coding benchmarks.

Sharp takeaway: this is a direct, shipping answer to the same key-value cache problem this curriculum keeps circling, and it takes a different tack than Kimi Delta Attention's approach from earlier this month. Where Kimi K3 mostly replaces attention with a fixed-size recurrent state and only falls back to full attention every fourth layer, DeepSeek keeps something closer to real attention everywhere, but makes it selective and compressed rather than recurrent, retrieving only the handful of blocks that matter for a given query instead of summarizing everything into one running state. Both are legitimate answers to the same underlying constraint, that a growing key-value cache is fundamentally a memory problem; which one you'd reach for depends on whether you need every token theoretically retrievable, which favors DeepSeek's sparse-retrieval approach, or you're willing to trade some exact recall for a smaller, constant memory footprint, which favors the recurrent approach. Worth learning both before you pick a serving stack for anything with genuinely long context.

Story two. A widely shared but still unreviewed claim says a version of OpenAI's newest model closed a thirty-year-old gap in convex optimization theory, and the honest story here is as much about how fragile that claim still is as about the result itself.

Researchers benchmarking GPT-5.6 Sol Pro's mathematical reasoning, building on earlier work where the same family of models produced a correct, verified proof improving a known convergence bound in convex analysis, are now circulating a new result: a lower bound showing that a specific class of convex optimization problems requires on the order of d-squared function evaluations to solve, matching the complexity of an existing algorithm that's been the best known approach for three decades. If it holds up, it would mean that algorithm is provably as good as this kind of approach can get, closing a question researchers have return to for years without settling it. The catch is right there in how it's being shared: this is a social-media-circulated claim, explicitly flagged by the people posting it as not yet peer reviewed, sitting alongside a separate, higher-profile claim from earlier this month that the same model family produced a proof of a fifty-year-old graph theory conjecture using sixty-four parallel subagents exploring different proof strategies at once, a claim independent mathematicians have already partly pushed back on for missing citations to foundational prior work despite the underlying argument being sound.

Sharp takeaway: the methodology matters more than either individual claim right now, and it is genuinely new. Running many parallel reasoning branches at high test-time compute against a single hard problem and letting the branches attempt different strategies is a real capability worth tracking regardless of whether this specific lower bound survives review. But this show's rule about self-reported benchmarks applies with extra force to results announced on social media before anyone outside the original claimant has checked them: treat a lower bound in this category as an interesting hypothesis a frontier model helped generate, not as settled mathematics, until an independent group works through the proof line by line.

Story three. Google's Gemini three point five Pro missed its own deadline for a third time this week, and the reason is more structurally interesting than the delay itself.

Gemini three point five Pro was originally targeted for June, slipped to a rebuilt version targeted for July seventeenth, and has now missed that date too, with internal testing reportedly still turning up frequent hallucinations and inconsistent coding output after Google abandoned the prior Gemini two point five Pro architecture for a ground-up redesign built around a two-million-token context window and what the company calls a deep-think reasoning layer. Google reset and retrained on updated data once already in late June specifically to fix the coding regressions, and the internal results were reportedly disappointing again. The detail worth remembering is organizational, not architectural: separate teams inside Google Cloud, DeepMind, and the Android division are reportedly building their own AI coding tools in parallel, competing for the same limited training and serving hardware rather than pooling it, which is the kind of internal fragmentation that makes hitting a single coordinated launch date harder every time it recurs.

Sharp takeaway: a from-scratch architecture rebuild is a legitimate reason for a model to slip once. Missing the same self-imposed deadline three times, with the stated blocker being the same coding-quality regression each time, points at something other than the difficulty of the underlying research problem, most likely resourcing and coordination overhead across duplicated internal efforts competing for the same graphics processing units. If you're evaluating whether to build around a not-yet-shipped model from any lab, a pattern of repeated slips on the same specific capability is a better signal to weight than the marketing description of what the eventual model will do.

Story four. Isomorphic Labs, DeepMind's drug-discovery spinout, unveiled a unified model that more than doubles AlphaFold three's accuracy on a hard structure-prediction benchmark, and it's aimed squarely at the step after you've predicted a protein's shape.

The Isomorphic Labs Drug Design Engine handles four linked capabilities in one system: predicting how a small-molecule drug candidate binds to a target protein's structure, estimating the strength of that binding numerically, identifying cryptic pockets on a protein surface that aren't visible in a static structure but open up as a target for a drug to bind to, and modeling how antibodies interact with the antigens they're built to recognize. On a challenging protein-ligand structure prediction generalization benchmark, meaning test cases built specifically to include target-drug combinations unlike anything in the training data, the system's accuracy came in at more than double AlphaFold three's, and its binding-affinity estimates reportedly beat the accuracy of gold-standard physics-based simulation methods that have been the field's reference point for decades. The announcement landed alongside a one point two billion dollar funding round, but the technical claim stands on its own: this is a step toward collapsing structure prediction and the actual drug-design decisions that follow it into one system, rather than treating them as separate stages with separate tools.

Sharp takeaway: the transferable idea here isn't specific to biology. AlphaFold's original breakthrough solved a narrow, well-defined prediction problem, the shape a protein folds into; this is the harder, less clean follow-on question of what you do with that shape once you have it, and doing meaningfully better than physics-based simulation on binding affinity, if it holds up under outside scrutiny the way AlphaFold's original claims eventually did, is a sign the approach transfers past pure structure prediction into decision-relevant numbers a chemist would actually use. Worth watching whether independent labs can reproduce the binding-affinity numbers on their own benchmark sets rather than the company's own generalization set.

Story five. Apple's trade secrets fight with OpenAI widened this week from a handful of named engineers to roughly forty former Apple employees now working there, and the detail worth noticing is which department it's about.

Apple sued OpenAI last week alleging a coordinated effort to obtain confidential hardware engineering and product-development information, naming OpenAI's chief hardware officer, a twenty-four-year Apple veteran, and a former senior Apple electrical engineer now on OpenAI's hardware team, among the individuals it says carried proprietary designs and manufacturing processes with them. This week Apple sent legal preservation letters, formal notices requiring recipients to retain any potentially relevant documents and communications, to dozens of additional former employees now at OpenAI, on the theory that the alleged misconduct extends well beyond the handful of people named in the original complaint; Apple's filing reportedly counts more than four hundred former Apple employees currently working at OpenAI overall. OpenAI has denied the allegations, saying publicly it isn't aware of evidence the complaint has merit.

Sharp takeaway: what makes this worth tracking isn't the lawsuit mechanics, it's what it signals about where OpenAI is spending its hiring effort. A trade-secrets fight this specifically aimed at hardware engineering and manufacturing process talent, rather than software or model-training staff, is a reasonably direct tell that OpenAI's device ambitions are further along and more resourced than its public roadmap has said out loud. Whether or not any particular trade secret changed hands, the shape of who got sued is itself information.

Now, what to watch. Watch for independent benchmarking of DeepSeek V4-Pro's hybrid attention against real long-context retrieval tasks, not just its own reported compute and cache numbers, the same way this show waited for outside verification on Kimi K3's architecture claims. Watch whether the convex optimization lower bound gets picked up and checked by an optimization theorist working through the proof independently, the same scrutiny the Cycle Double Cover proof got and partly failed on citation grounds; a viral claim and a verified result are very different things, and this one is squarely still the former. Watch whether Gemini three point five Pro actually ships before its own developer conference commitments run out, since a fourth slip would move this from an engineering story into a credibility one. And watch whether other labs racing to build in-house hardware, not just Apple and OpenAI, start pointing lawyers instead of recruiters at each other's alumni networks, since a trade-secrets fight this specifically shaped tends to be a leading indicator that more than one company sees hardware as the next real battleground.

Today's clearest deep-dive candidate is DeepSeek V4's hybrid attention architecture, not because compressed attention is a new idea on its own, but because this curriculum keeps returning to the key-value cache as the core memory problem behind long context, and this is a second, differently-shaped shipping answer to it worth understanding side by side with Kimi Delta Attention. Working through exactly how the compression ratio, the four-bit lightning indexer's block selection, and the small exact local window trade off against each other, and why that combination gets to ten percent of the cache at only a mild accuracy cost, is the kind of detail that would actually change which long-context architecture you'd reach for. It's going into the curriculum as a deep-dive candidate.
